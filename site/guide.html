Architecture guide · sieve

How Sieve decides which tests to run.

Sieve maps a Git change to the JVM tests it can reach and runs them through the project's own Maven or Gradle build. Three selection paths share one rule: when the evidence runs out, widen the selection, all the way to the full suite.

01

Big picture

One binary holds the selector, the build adapters, the validation tooling and, by default, an embedded Java agent. It reads Git and impact.json, then starts the native build with arguments that limit which modules build and which tests run.

02

Selection modes

Every path ends in a Selection (src/main.rs) with one of four modes. select prints it; run --output writes it before the build starts.

ALL

Full suite, every module.

no base · no history · build input · stale fingerprint
MODULES

Changed modules and every module that depends on them.

verify -pl … -am · :m:check
SUBSET

Named test classes inside the selected modules.

class-level · local mode
NONE

No tests. Module-level: clean only. Class-level: compile and verify.

ignored paths · unreached
// sieve select --workspace projects/maven --base HEAD   (after editing TaxRules)
{
  "mode": "MODULES",
  "modules": ["checkout", "pricing"],
  "changed": ["pricing/src/main/java/example/TaxRules.java"],
  "reason": "Changed source/resource modules and their transitive dependents"
}
Rule

Uncertainty widens the selection and analysis errors fall back to the wider mode. Invalid configuration and build failures fail the command instead: a fallback must never hide a broken setup.

03

Static path

sieve run --base REV, used in CI and for multi-module or Gradle projects. Every question that cannot be answered safely routes to ALL.

Step by step main.rs

  1. Read configurationConfig::read

    Tool, module graph, ignore globs, opt-ins. Unknown fields, missing modules or paths outside the workspace are errors, not fallbacks.

  2. Collect changeschanged_paths

    Merge base of REV and HEAD; committed, staged, unstaged, deleted, renamed and untracked paths. Submodule updates count even when Git configuration ignores them.

    no history → ALL
  3. Check the fingerprintfingerprint.rs · setup::stale

    Hash of POMs, Gradle scripts, .mvn/, gradle/, buildSrc. A mismatch means the declared graph may be stale: a module selection asks the build for its graph and stands only if impact.json still declares every module, edge, and shared test module.

    graph changed → ALL · run sieve refresh
  4. Classify pathsConfig::select

    Ignored → skip. <module>/src/** → that module. Default ignore patterns never hide module sources (a module named docs still counts); explicit ones do.

    other → ALLonly ignored → NONE
  5. Close over dependentsConfig::select

    Repeat until stable: a module with a selected dependency becomes selected. A change under src/test/ passes on only from modules listed in shared_tests.

    → MODULES
  6. Refine to classesSelection::refine

    Only with class_level, only in run. See section 04.

    → SUBSET→ NONEfallback keeps MODULES
  7. Run the native buildbuild_args

    Write --output, delete stale Surefire/Failsafe reports outside the reactor, start the build, return its exit status.

04

Class-level analysis

Module selection runs every test of a module, and a single-module project has only one. Opt in with "class_level": true and run compiles the selection, then follows bytecode from changed classes to test classes.

  1. Subtypes. A changed or affected type affects its subtypes.
  2. Implementations. A changed implementation affects callers of its interfaces and superclasses (DI, ServiceLoader), not sibling implementations. Decorators count as callers.
  3. Inlined constants. Changed non-private static final constants and Kotlin const vals affect every class whose source names them, repeated for derived constants, plus every class without a findable source.
  4. Kotlin inline functions. A caller keeps a copy of an inline body, not a call. Its SourceDebugExtension source map names the file the copy came from (as a path, or as kotlinc 2 writes it, the class compiled from it), so a changed body affects every class that inlined it, across modules.
  5. Components. A reached DI component selects every context test (Spring, Micronaut, Quarkus, Helidon, Weld, Arquillian, Modulith), narrowed by Spring Boot slice rules.
  6. Scanning tests. ArchUnit, Modulith ApplicationModules, package-selecting suites, Cucumber, ClassGraph and Reflections leave no reference, so any change selects them.
  7. Named in text. A class named in Spring XML, logging or a library service file under src/ that reaches a change falls back to MODULES; spring.factories and *.imports classes join every context instead.

Why a test was selected reasons

a.ServiceTest → a.Service → a.Api, implemented by a.Impl (changed)

--output lists one chain per selected test. Maven gets a Surefire/Failsafe excludes file with the unselected classes (plus the default **/*$*), so POM includes and the unit/integration split survive; Gradle's Test tasks filter to what impactSelect wrote. Static analysis still cannot see reflection built from non-constant strings, resources outside src/, context annotations composed in library jars, or unlisted frameworks.

05

Build adapters

Sieve never replaces the build. It passes properties and scopes to the build tool it found, preferring the project's wrapper.

Maven setup.rs

sieve init reads effective models, writes the graph and fingerprint, and adds per-module impact.skip.<module> properties wired to Surefire/Failsafe skipTests. -am dependencies compile, test JARs still work, their tests stay skipped.

Edges
declared deps, sibling build plugins, plugin deps, processor paths, unpacked artifacts, sibling dirs in config

Gradle gradle.init.gradle

A bundled init script passed with --init-script. No build-file edits, Groovy and Kotlin DSL, configuration-cache safe, Gradle 7.6.3+.

impactInit
reports the project graph for init
modules
-Pimpact.modules disables other Test tasks
tests
impactSelect runs sieve classes after compiling; Test tasks filter to its selection
classes
impactCompile, impactClasses

sieve refresh reruns discovery after build changes and keeps extra edges between surviving modules and the class_level choice. Modules may be nested when their directories match their place in the build (services/orders); setup refuses other custom layouts, composite builds, Android and Kotlin Multiplatform rather than guessing.

06

Local mode

Static analysis runs every Spring context test for any component edit. Runtime records narrow that on developer machines and, with --ci, in CI: single-module Maven or Gradle, Java 17+ test JVM, one build start. Opt in with sieve run --records or "records": true. ADR 0001 · ADR 0002 · ADR 0003 · ADR 0004 · ADR 0005

Agent pieces agent/src/sieve

ClassRole
BootEntry point compiled for Java 8, since JDK_JAVA_OPTIONS reaches every java launch. Hands off on Java 17+.
AgentReads the options file written by sieve; stays inactive in the build tool's own JVM.
TransformerVendored ASM, relocated to sieve.agent.asm: method-entry probes on project classes, entry probes on library classes that report their jar, file probes on JDK file APIs.
Probe · BucketBootstrap-loaded sinks: methods and files per test class, per context startup, and the rest. Never touch files.
FilterJUnit PostDiscoveryFilter: drops the classes sieve decide lists, prunes emptied containers.
ListenerAttributes probe hits to the running top-level class, records outcomes, detects parallel execution.
spring/*ContextHook, ContextUse, BootRun: startup work counts for every class using the context, cached or not.
StatePer-JVM state and the subprocess conversation with the binary. Sends the raw context (agent options, system properties, JVM arguments) on standard input; sieve filters and hashes it.

Records check invocation arguments, stable JVM properties (minus record_ignore_properties and version-plugin values) and environment variables declared under record_env. With --ci, machine-specific paths become placeholders and host identity is left out, so records restored from the CI cache hold in another checkout. Library jars are evidence too: a dependency bump reruns the tests that ran the bumped jar, and an added or removed artifact reruns everything. sieve env uses separate callback files; its callbacks run every test and write no records while a local wrapper owns the workspace lock. Ordinary Maven or IDE builds can still alter native outputs; output fingerprints invalidate the shortcut and classes rewritten during tests prevent recording.

Native verify packaging stays enabled. The reuse, mvnd and repackage speed-ups are opt-in through --with; jgitver is skipped by default where Maven loads it, since the version it stamps on every commit would invalidate records (--without jgitver keeps it). Records still assume observed paths cover test behavior and tests are independent; undeclared environment inputs, external services, floating image tags and jars changed without a build-input change need full-suite validation.

build.rs compiles the agent with any JDK 17+ javac: the probe, API stubs and vendored ASM for 17, Boot for Java 8, the rest for 17. It embeds both jars with include_bytes!, so binary and agent cannot drift. --no-default-features leaves the agent and local mode out.

07

Validation

The oracle is independent: selector code never reads expectations, and expectations are never weakened to make a selector pass.

CommandWhat it proves
fixtures verifyEach mutation in scenarios.json on projects/maven and projects/gradle: executed JUnit XML covers the required tests and expected failures.
fixtures benchmarkAlternates native, --full and selected runs; every sample must pass the oracle before timing counts.
replayReal first-parent history: selection per commit; with --run, missed failures against the full suite; --walk for local mode.
catalogFeedback time per edit kind; --plant injects bugs into changed bodies and fails on any missed failure.
classifyWeights edit kinds by recent commits.
--test nativeHand-written mutations of every sample, Kotlin ones included: native full build against module- and class-level runs, with exact classes, invocation counts and failures.
--test recordsLocal mode end to end on Maven and Gradle: records, Spring contexts, --ci records in another checkout, and Dependabot-style version bumps of real dependencies.

09

One change, three outcomes

Edit pricing/src/main/java/example/TaxRules.java in projects/maven, where checkout depends on pricing and runtime stands alone.

i

Module-level

MODULES

The path marks pricing; closure adds checkout. 10 test classes, 12 invocations. The 5 runtime integration tests are skipped.

ii

Class-level

SUBSET

Both modules compile; only test classes whose bytecode leads to TaxRules run, each with a reason chain.

iii

Plus a POM edit

ALL

Add a dependency to pricing/pom.xml in the same change: the fingerprint no longer matches and the path is a build input.

# try it
sieve fixtures prepare --tool maven --dest /tmp/impact-tax --git
sieve fixtures apply tax-transitive --workspace /tmp/impact-tax
sieve select --workspace /tmp/impact-tax --base HEAD
sieve run    --workspace /tmp/impact-tax --base HEAD   # fails on purpose: the mutation breaks tax tests
10

Invariants worth keeping

A change that breaks one of these needs a new decision, not a patch.

  1. Unknown or unclassified change → ALL; analysis error → the wider selection.
  2. Build and test failures propagate. Only fixture mutation runs ignore test failures.
  3. Selection JSON is written before tests run, outside the workspace or in an ignored folder.
  4. scenarios.json stays independent of selector code.
  5. Probes never change observed behavior; a possibly unrecorded read discards the run's records.
  6. The default branch keeps a full-suite job; CI selection, static or from --ci records, only shortens pull requests.
