sieve · Maven · Gradle · Jest · Vitest

Run the tests a change can reach. Skip the rest.

Sieve reads the diff and runs only what it can reach: the changed modules and their dependents, the test classes whose bytecode leads to the change, or the tests whose last run touched it. Your own Maven, Gradle, Jest or Vitest build runs them. A build file, a lockfile, or a base Git cannot see still runs everything.

−57% build time over 30 commits of apache/commons-text. −52% on a 20 commit Spring Boot benchmark, with no real failure missed.

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
    persist-credentials: false
- run: |
    curl -fsSL "https://raw.githubusercontent.com/preacherxp/sieve/$SIEVE_VERSION/install.sh" | sh
    echo "$HOME/.local/bin" >> "$GITHUB_PATH"
  env:
    SIEVE_VERSION: <tag>
- run: |
    args=(--full)
    if [ "$EVENT" = pull_request ]; then
      args=(--base "$BASE")
    fi
    sieve run --workspace . "${args[@]}"
  env:
    EVENT: ${{ github.event_name }}
    BASE: ${{ github.event.pull_request.base.sha }}

Run sieve init once and commit impact.json. Set SIEVE_VERSION to a release tag you have verified; the installer checks its checksum and needs neither Rust nor a JDK. Pull requests select against their base; every other event runs the full suite.

New since 0.3.0 ON MASTER

  • init edits no POM.

    The embedded Maven extension skips the tests of the upstream modules -am builds. impact.json is the only file to commit.

  • Docs commits start no build.

    A docs or CI only change used to start Maven or Gradle just to clean, 1 to 3 s each. Now nothing starts.

  • Comment edits select nothing.

    Javadoc, comment and formatting changes change no class. On commons-text they had selected 39 and 64 of its 103 test classes.

  • Gradle keeps its cache and daemon.

    An identical selection restores :test from the build cache, and the project's daemon setting decides. 22 fixture scenarios: 88 s down to 22 s.

  • Class files parse on every core.

    47,000 classes from real jars load in 1.3 s instead of 6.3 s.

  • Jest and Vitest.

    sieve init finds the source roots and maps each script to the test files that import it. Config, lockfile and setup file edits still run every test.

These are on master and ship in the next release. To use them now, install from source: cargo install --git https://github.com/preacherxp/sieve --locked. The installer and the CI job fetch the latest release, 0.3.0.

A shorter job, not a guessed one.

  1. 01

    Read the real graph.

    init asks Maven or Gradle for the module graph, or finds your Jest or Vitest source roots, and writes impact.json. It will not overwrite one. Checkout depending on pricing is an edge the selector can walk.

  2. 02

    Diff against the base.

    Committed, staged, unstaged, deleted, renamed, and untracked paths. A file under module/src/ selects that module and every transitive dependent.

  3. 03

    Let the build tool run them.

    Maven gets clean verify -pl the selected modules -am, and skips the tests of the upstream ones. Gradle gets clean :module:check. With "class_level": true, the same build runs only the test classes whose bytecode reaches the change. No base, or a build file change, and the full suite runs.

Where it will not save time.

  • Test classes are opt in. By default you skip modules: TaxRules.java also runs CurrencyLabelTest, because they share pricing. class_level narrows to test classes inside the same build, Kotlin inline functions and constants included. Anything it cannot map runs the whole module.

  • Unsafe diffs run the full suite. pom.xml, Gradle build scripts, package.json and lockfiles, impact.json, or a base Git cannot resolve: nothing is skipped. A wrong skip is worse than a slow job.

  • Docs are the free case. README.md, docs/, and any ignore globs in impact.json do not compile or test. On master, no build starts at all.

  • Setup expects a regular layout. One package, or modules at any depth whose directories match their place in the build. Other directories, composite builds, Android, and Kotlin Multiplatform are reported, not invented.

  • Records need one module. Local mode (--records) records what each test class ran and read, on single-module Maven or Gradle with a Java 17+ test JVM. A dependency bump then reruns only the tests that ran the bumped jar. --ci shares records through the CI cache.

  • Keep the full suite somewhere. Selection assumes tests are independent and that the inputs it sees are all there is. Run everything on the default branch, so a missed failure fails at merge, never silently.
