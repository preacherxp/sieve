How a change becomes a decision.

    

      

        
13 / 14

        
Test classes and invocations in the full sample suite.

      

      

        
18

        
Fixture scenarios. The selector never reads the oracle.

      

      

        
0

        
Class-level guesses. The grain is the module.

      

    

    
    
      
  1. 
        
    
          
    Find the merge base.
    
          
    Compare --base with HEAD. No base, or Git that cannot answer, and the decision is ALL. --full asks for that outright.
    
        
    
      
    2. 
      
  2. 
        
    
          
    Take every path.
    
          
    Committed, staged, unstaged, deleted, renamed, and untracked. Paths outside the workspace that are not README.md, VALIDATION.md, or docs/ also force ALL.
    
        
    
      
    3. 
      
  3. 
        
    
          
    Walk the edges backwards.
    
          
    A file under module/src/ selects that module, then every transitive dependent. Pricing pulls checkout in. Checkout does not pull pricing back. Docs are ignored. Anything else — a POM, a build script, impact.json — selects ALL.
    
          
    {
  "tool": "maven",
  "modules": {
    "pricing": [],
    "checkout": ["pricing"],
    "runtime": []
  }
}
    
        
    
      
    4. 
      
  4. 
        
    
          
    Hand the decision to the build.
    
          
    Maven runs clean verify. Gradle runs clean check, with a bundled init script so neither build.gradle nor build.gradle.kts has to change. NONE stops after clean. The run starts with clean so stale reports cannot linger.
    
        
    
      
    5. 
    


    

      
Put it on a project.

      
Setup detects Maven or Gradle, prefers a wrapper you already have, and writes impact.json. It will not overwrite one. Commit the config. Maven also gets small skip profiles in the module POMs.

      

        cargo install --git https://github.com/preacherxp/sieve --locked
        
      

      

        java-test-impact init
        
      

      

        java-test-impact run --workspace . --base origin/main
        
      

      
From this checkout: cargo install --path . --locked. Preview without running tests: java-test-impact select --workspace . --base origin/main. Use your real comparison branch. Rust 1.92 or newer, Git, and the JDK your build already needs.

    

  


  

    

      
Limits

      
It would rather run everything than guess.

      
    
        
  • 
          
    Module grain, on purpose.
    
          
    No class graph and no recording agent. CurrencyLabelTest runs when TaxRules.java changes, because they share a module. That is the conservative policy, not a miss.
    
        
    • 
        
  • 
          
    Unknown input closes the sieve.
    
          
    Build scripts, dependency versions, impact.json, a deleted module path, or a base Git cannot resolve: mode ALL. Invalid configuration fails instead of improvising.
    
        
    • 
        
  • 
          
    Setup only knows a simple layout.
    
          
    One package, or direct child modules whose directory names match. Nested trees, Gradle composite builds, Android, and Kotlin Multiplatform are reported, not guessed.
    
        
    • 
        
  • 
          
    The graph has to be true.
    
          
    Keep impact.json complete when you add dependencies, including runtime and resource edges. Init refuses to overwrite it. Ordinary Maven and Gradle commands still run the full suite.
