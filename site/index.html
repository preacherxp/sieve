java-test-impact · Maven · Gradle

Reduce CI time on Java and Kotlin changes.

Sieve runs tests only in the modules a diff can affect, and in every module that depends on them. The rest of the suite is not started. A build file, or a base Git cannot see, still runs everything.

  1. cargo install --git https://github.com/preacherxp/sieve --locked
  2. java-test-impact init
  3. java-test-impact run --workspace . --base origin/main

From this checkout, cargo install --path . --locked. Preview a job with select instead of run. Use your real base branch. Rust 1.92+, Git, and the JDK the build already needs.

A shorter job, not a guessed one.

  1. Read the real graph.

    init asks Maven or Gradle for the module graph and writes impact.json. It will not overwrite one. Checkout depending on pricing is an edge the selector can walk.

  2. Diff against the base.

    Committed, staged, unstaged, deleted, renamed, and untracked paths. A file under module/src/ selects that module and every transitive dependent.

  3. Let the build tool run them.

    Maven gets clean verify and skip flags. Gradle gets clean check and -Pimpact.modules. No base, or a build-file change, and the flags stay off so the full suite runs.

Where it will not save time.

  • The grain is the module. TaxRules.java also runs CurrencyLabelTest, because they share pricing. You skip modules, not individual classes. There is no recording agent.
  • Unsafe diffs run the full suite. pom.xml, Gradle build scripts, impact.json, or a base Git cannot resolve: nothing is skipped. A wrong skip is worse than a slow job.
  • Docs are the free case. README.md, VALIDATION.md, and docs/ do not compile or test. The job cleans and stops.
  • Setup is for a simple layout. One package, or direct child modules whose directory names match. Nested trees, composite builds, Android, and Kotlin Multiplatform are reported, not invented.
